# DocJev-bench · 文档证据驱动的业务决策评测

[数据集](https://huggingface.co/datasets/Immortal-Zhang/DocJev-Bench) &nbsp;&nbsp; [English](benchmark.md) &nbsp;&nbsp; [mJev-Doc](README.zh-CN.md)

**一份文档，多个判断，明确规则，可比较的决策。**

DocJev-bench 评测文档处理中的关键能力：找到证据、比较字段、核验明确要求，以及选择下一步处理方式。它可用于评测 mJev-Doc，也可用于比较其他文档模型。

```text
文档图片 + 题目给定的规则 + 候选处理方式 → 决策
```

当前包含 608 张图片、2617 对中英文题目、5234 条语言记录。同一页面可以有多个实质不同的问题，候选集合随任务变化。

## 面向哪些业务环节

| 业务环节 | 评测模型需要完成的判断 |
| --- | --- |
| 材料接收 | 识别文档类别、目的和相关可见元素 |
| 信息复核 | 比较字段，核对不同表格或区域中的数据关系 |
| 完整性检查 | 按给定清单判断所需字段是否齐备 |
| 条件筛选 | 将阈值和多条件规则应用到文档中的事实 |
| 复核分流 | 根据题目给定的规则，选择处理或复核路径 |
| 行动选择 | 选择规则要求的下一步动作、注释或处理结果 |

这些任务用于评估文档处理组件。当前 benchmark 按题目评测候选答案，不执行实际审批系统。适用规则在题目中明确给出，不把它们当作真实机构制度、法律或财务规范。

## 任务设计

同一页面包含多个不同类型的问题，答案需由页面证据和题目规则支持。每题候选数量随任务而定，中英文版本共享图片与参考答案，可以按语言或题型分别比较。

## 如何评测文档决策组件

向模型提供图片、题目和候选项，参考标签不进入提示词；将模型选择与保存的参考答案比较。按语言和题型报告 Accuracy，候选重排实验可以额外报告 Permutation Consistency。

当前任务格式为 Choice。模型可以返回候选相对概率；数据集没有提供参考概率分布或连续业务分数。中英文是对应观察，使用[评测指南](evaluation.md)中的协议，并区分直接看图与 OCR 加文本模型的评测方式。

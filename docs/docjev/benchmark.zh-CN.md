# DocJev-bench · 文档证据驱动的业务决策评测

[数据集](https://huggingface.co/datasets/Immortal-Zhang/docjev-bench) · [English](benchmark.md) · [mJev-Doc](README.zh-CN.md)

**一份文档，多个判断，明确规则，可比较的决策。**

DocJev-bench 评测文档处理中的关键能力：找到证据、比较字段、核验明确要求，以及选择下一步处理方式。它是可单独使用的 benchmark 资产，与 mJev-Doc 文档模型配套。

```text
文档图片 + 题目给定的规则 + 候选处理方式 → 决策
```

当前包含 220 张图片、1,512 对中英文题目和 21 种任务类型。同一页面可以有多个实质不同的问题，候选集合随任务变化。

## 面向哪些业务环节

| 业务环节 | 评测模型需要完成的判断 |
| --- | --- |
| 材料接收 | 识别文档类别、目的和相关可见元素 |
| 信息复核 | 比较字段，核对不同表格或区域中的数据关系 |
| 完整性检查 | 按给定清单判断所需字段是否齐备 |
| 条件筛选 | 将阈值和多条件规则应用到文档中的事实 |
| 复核分流 | 根据题目给定的规则，选择处理或复核路径 |
| 行动选择 | 选择规则要求的下一步动作、注释或处理结果 |

这些任务用于评估文档处理组件。当前 benchmark 按题目评测候选答案，不执行实际审批系统。适用规则在题目中明确给出，不把它们当作真实机构制度、法律或财务规范。

## 核心设计亮点

- **文档证据与决策结合。** 答案需要把页面信息与要求作出的判断联系起来。
- **同页多任务。** 一张图片从不同任务角度提出多个问题，便于观察模型在同一文档上的能力差异。
- **规则作为输入。** 明确 criteria 使条件决策可以复现，也便于检查候选选择的依据。
- **动态候选集合。** 保留 2、3、4、5 或 7 个候选，参考答案可以直接用于 Jev 风格的候选评分。
- **中英文逐题对应。** 两种语言共享图片和参考候选，支持分语言与对应题比较。

## 同一页面，多个业务判断

当前 benchmark 的文档 `000002` 是一页财务报表，其题目展示了同一份证据上的不同判断环节：

| 题目对编号 | 题目明确给定的规则 | 参考候选 |
| --- | --- | --- |
| `000002_08` | 筛选 2022E–2024E 中速动比率 ≥ 1、资产负债率 < 35% 的年度 | 2023E 与 2024E |
| `000002_09` | 对 2023E，经营活动现金流低于净利润且营运资金变动为负时，转交现金流复核；题目同时定义其他分支 | 现金流复核组 |
| `000002_10` | 以 2024E 经营活动现金流覆盖投资、筹资流出，再根据剩余资金选择处理方式 | 保留余额 |

这些规则是题目写明的评测假设。完整题干、候选集合和中英文版本见[数据集](https://huggingface.co/datasets/Immortal-Zhang/docjev-bench)，对应图片为 `images/000002.jpg`。

## 如何评测文档决策组件

向模型提供图片、题目和候选项，参考标签不进入提示词；将模型选择与保存的参考答案比较。按语言和题型报告 Accuracy，候选重排实验可以额外报告 Permutation Consistency。

当前任务格式为 Choice。模型可以返回候选相对概率；数据集没有提供参考概率分布或连续业务分数。中英文是对应观察，使用[评测指南](evaluation.md)中的协议，并区分直接看图与 OCR 加文本模型的评测方式。

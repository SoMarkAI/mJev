# 可靠性修复 — 2026-09-26

本次修复接口、报告和实验 runtime 的边界问题，不改变模型权重、注意力公式或分数计算。历史显式配置的实验保留原始记录。

## 行为变化

- 主 HF／vLLM CLI 和评分接口统一默认 `causal`。依赖旧 vLLM 默认行为的调用方，需要显式传入 `isolated` 才能保留原注意力模式。
- 配对报告的全部正确性统计与参考答案分类来自冻结 manifest。结果行的标签、数据集、模态或参考类型冲突时拒绝生成报告；记录 manifest 哈希并检查逐模式完整覆盖。
- 原地重跑报告和媒体审计时，先撤销旧完成标记；完整报告写入后最后生成 `_SUCCESS`。要求新输出目录的推理脚本继续拒绝复用，不修改已完成实验。
- 模型验证脚本对 `video` 和 `audio_video` 都传递采样参数；测试覆盖验证脚本边界以及 Omni 媒体处理器调用。
- CLI 预检查、推理和评分 API 共用结构校验。空问题列表和乱序候选字典在模型加载前报错；`demo_hf.py` 分离参数解析、预检查、评分和输出。
- 实验 HTTP 媒体读取执行目录限制、文件／data URL 大小限制和显式 HTTPS 主机白名单，向 vLLM 传递已验证的字节。补丁失败终止启动，增加版本与 hook 就绪校验，删除重复路由。见 [runtime 配置](integrated.zh-CN.md#媒体访问与启动检查)。
- 分组评测逐媒体组原子保存，并同步保存累计预测与进度。后续失败保留已完成工作，尚不支持自动断点续跑。

## 实际检查

- 本地 Python 3.11：**175 项通过**，跳过四个依赖可选 vLLM 的模块。
- 固定 Linux vLLM 0.25.1 环境：**184 项 CPU 测试通过**，包含 API 集成检查。
- 在该固定版本上实际安装实验 runtime hooks：五项必要标志全部就绪。
- 故障注入覆盖参考答案冲突、成功后缺行重跑、目录越界／符号链接／大小限制、非公网远程地址／重定向、部分补丁失败和后续媒体组失败。

这些是软件回归检查。本次未新增全权重 GPU 推理、HTTP Tree-KV 一致性或性能排名结论；已有 GPU 记录仍只对应各自执行的源码快照。

## 仍需补充的研究证据

问题数／输入规模的延迟与峰值显存扫描，以及带原始标签、去媒体和候选顺序对照的任务评测，都值得另做固定实验；它们不是代码修复，也不是当前已有证据。跨项目比较需要逐仓库核对，本次仅明确“不同问题分支独立”和“同题候选隔离”的区别。候选隔离保留为可控实验结构，不能据此宣称准确率上限更高。
